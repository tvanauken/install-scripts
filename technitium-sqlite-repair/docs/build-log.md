# Build Log: Repair Technitium Corrupted SQLite Database Errors
### Van Auken Tech · Thomas Van Auken

## Objective
Create an automated script to handle the "SQLite Error 11: database disk image is malformed" error generated by the Technitium DNS Server's "Query Logs (Sqlite)" app. The error breaks the query log viewing functionality until the corrupted `.db` file is removed or replaced.

## Research & Diagnosis
1. Encountered `SQLite Error 11` when accessing the `Logs > Query Logs` page in the Technitium interface.
2. Verified the issue through Technitium GitHub issue tracker which indicated corruption usually occurs if the service does not shut down gracefully.
3. The official fix requires deleting the corrupted `.db` file manually or changing the database file path. 
4. Designed an automated solution for the environment: stopping the service, finding `.db` files in the app directory, deleting them, and restarting the service.

## Implementation Details
1. **Directory Structure & Naming:**
   - Script directory: `technitium-sqlite-repair`
   - Main script: `technitium_sqlite_repair.sh`
2. **Visual Standards:**
   - Followed existing visual design cues (color variables, `msg_info`, `msg_warn`, `msg_ok`, `msg_error` functions).
   - Generated a banner block similar to existing tools in the Van Auken Tech script collection.
3. **Execution Steps:**
   - Pre-flight check for `root` privileges.
   - Verified that `dns.service` is available.
   - Executed `systemctl stop dns.service`.
   - Purged `.db` files located inside `/etc/dns/apps/Query Logs (Sqlite)/`.
   - Executed `systemctl start dns.service`.
   - Final verification using `systemctl is-active dns.service`.
4. **Testing:**
   - Executed manually on the live environment and successfully resolved the query logs error without requiring manual API calls or tokens.
   - Tested robustly over different scenarios (e.g. file missing, service stopped) and handled gracefully.
